# Ревизия фундамента Aurora — 23 сентября 2026

## Зафиксированная архитектура

Aurora — локальный живой справочник. Пользовательский JAR отвечает за интерфейс, безопасный запуск Ollama,
поиск по установленным профилям и формирование ответа. Факты находятся во внешних версионированных архивах.
Во время игры мод не читает NEI, реестры рецептов, таблицы дропа или внутренности других модов.

Генераторы профилей являются отдельными инструментами разработки. Они не входят в пользовательский JAR.

## Что исправлено

- Удалены ридеры активных рецептов, блоков и MobsInfo со всеми связанными ветками.
- Удалён оставшийся автономный слой: наблюдение за здоровьем, огнём, смертью и инвентарём, журнал мира,
  очередь самостоятельных реплик и соответствующая конфигурация.
- Снимок игрового контекста теперь создаётся только в момент вопроса игрока.
- Поиск больше не пересчитывает токены каждой статьи при каждом вопросе. Поисковые поля индексируются при загрузке.
- Лимит профиля поднят с 2 000 до 50 000 статей, добавлен общий лимит размера и изоляция повреждённых статей.
- Повреждённая или дублирующаяся статья больше не отменяет загрузку остальных статей профиля.
- Наличие случайного или несовместимого `manifest.json` больше не считается установленной рабочей базой.
- Активация профиля и замена кэша каталога используют атомарное перемещение с безопасным откатом.
- ZIP-профили ограничены по размеру, распакованному объёму, числу файлов и защищены от выхода за целевую папку.
- Проверки версий ограничены безопасным числовым форматом без переполнения.
- Неудачно запущенный процесс Ollama теперь завершается и не остаётся в состоянии вечного ожидания.
- Ответ Ollama ограничен по размеру; снимок мира и игровой чат явно помечены как недоверенные данные.
- Запросы к модели и обслуживание каталога перенесены в разные фоновые очереди.
- Удалены неиспользуемые поля статей и устаревшая документация.

## Проверено

- Полная сборка, форматирование и Checkstyle проходят.
- Все 324 JSON-статьи текущего vanilla-профиля проходят автоматический валидатор.
- Заявленное в manifest число статей совпадает с фактическим.
- В пользовательском JAR отсутствуют ридеры и генератор каталога.
- Schema v2 поддерживает отдельные факты, условия, связи и ссылки на источники; старые статьи v1 остаются читаемыми.

## Оставшиеся слабые места

1. Поиск пока лексический. Его качество зависит от хороших русских/английских названий, aliases и tags. Для десятков
   тысяч статей текущая схема пригодна; для сотен тысяч понадобится компактный дисковый индекс.
2. Большинство существующих статей пока остаётся в старом формате v1 с полем `body`. Schema v2 уже введена, но
   миграция должна выполняться небольшими проверяемыми партиями без автоматического переноса недостоверных фактов.
3. Онлайн-каталог защищён HTTPS, ограничением на GitHub Releases и SHA-256 архива, но сам catalog.json пока не имеет
   цифровой подписи. Перед публичным распространением обновлений каталог следует подписывать.
4. В репозитории исходный профиль имеет версию 0.3.0, а опубликованный каталог и встроенный bootstrap указывают 0.2.0.
   Это не ломает текущую установку, но следующую редакцию нужно выпускать единым атомарным релизом.
5. Автоматических тестов поиска, установки/отката профиля и повреждённых архивов пока недостаточно. Build и
   Checkstyle ловят компиляционные ошибки, но не заменяют набор модульных и интеграционных сценариев.
6. Доступ к истории ванильного чата использует имена приватных полей Minecraft 1.7.10. Есть безопасный fallback,
   однако некоторые моды интерфейса могут сделать вкладку игрового чата недоступной.
7. Уже отправленный запрос Ollama нельзя отменить: при выходе из мира его результат отбрасывается, но локальная
   генерация продолжается до ответа или тайм-аута. Позже стоит добавить явную отмену HTTP-запроса.
8. Автоматический установщик пока рассчитан только на macOS, а bootstrap-профиль жёстко закреплён в коде.

## Следующий безопасный этап

Сначала заполнить первую партию блоков по schema v2 и создать тестовый набор вопросов для поиска. После этого
расширять vanilla-профиль блоками, мобами, дропами и механиками. GTNH-профиль следует начинать только после того, как
формат выдержит vanilla-каталог без ручных исключений.
